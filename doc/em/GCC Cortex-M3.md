## Предисловие

системный программист для [[em/embedded|embedded]] должен знать всю кухню подготовки бинарного образа прошивки

в книге приведён набор усложняющихся задач по применению [[GNU toolchain]] в [[Linux/Linux|Linux]]

## Форматы и секции

```sh
arm-none-eabi-gcc -v
```

для объектных и бинарных файлов большинство систем используют [[ELF]]

важное понятие -- [[ABI]] , для линковки библиотек необходима совместимость на уровне [[ABI]]

![[ABI.png]]

- [[API/API|API]] описывает интерфейс на верхнем уровне: модули, имена функций, типы
- [[ABI]] фокусируется на форматах линковки и вызовов на уровне машинного кода: регистры аргументов/результата, кодирование имён ([[Cpp/манглинг]])

Очень давно все объекты программ стали делить на три категории, и размещать их в соответствующих сегментах (секций) памяти:
- `.text` машинный код
- `.data` данные
- `.bss` неинициализированные данные

объектный файл состоит из секций (памяти), часть из них переносится в память целевой системы при загрузке программы, или прошивке

также есть служебные секции для компоновщика, отладчика,..
